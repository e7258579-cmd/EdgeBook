# EdgeBook — חוזה ה-Webhook (V01)

**מטרה:** להגדיר בדיוק מה ה-Pine שולח ל-Firebase Function, ומה ה-Function מחזירה ועושה. מסמך תכנון, עדיין לא ממומש בקוד.
**סימונים:** ✅ הוחלט · ⚠️ הנחה שלא אומתה · ❓ החלטה פתוחה

## 1. עקרונות

- ✅ ה-Pine **מדווח** על אות; ה-Function **מחליטה** אם לבצע. כל שדה מחיר או כמות בהודעה הוא **רמז** בלבד.
- ✅ גודל הפוזיציה נקבע **בצד השרת** (תקרת מניות + 1% מההון). `qtyHint` לא נאמן עליו.
- ✅ **כל הודעה מטופלת פעם אחת.** מפתח ייחודי מחושב בצד השרת: `symbol|event|barTime`. הודעה שנייה עם אותו מפתח נרשמת כ-`duplicate` ולא מבצעת כלום.
- ✅ ה-Pine שולח **רק בסגירת נר** (האסטרטגיה רצה פעם אחת לנר, `calc_on_every_tick = false`).
- ✅ הסיסמה (`secret`) נמצאת בגוף ההודעה, כי TradingView לא מאפשר כותרות מותאמות.

## 2. מבנה ההודעה (JSON)

שדות משותפים לכל הודעה:

| שדה | סוג | תיאור |
|---|---|---|
| `secret` | string | הסיסמה המשותפת |
| `v` | number | גרסת החוזה (`1`) |
| `event` | string | `"entry"` או `"exit"` |
| `symbol` | string | סמל המניה, אותיות גדולות |
| `barTime` | number | זמן **סגירת** הנר, ms מאז 1970 (`time_close`) |
| `tf` | string | מסגרת זמן בדקות, למשל `"1"` |
| `strategy` | string | גרסת האסטרטגיה, למשל `"V05"` |
| `session` | string | `"pre"` (פרה-מרקט) או `"regular"` |

שדות נוספים לכניסה (`event = "entry"`):

| שדה | סוג | תיאור |
|---|---|---|
| `price` | number | מחיר הכניסה המשוער (הטריגר, או הפתיחה אם היה Gap) |
| `stop` | number | שפל הנר האדום האחרון, רמת הסטופ |
| `trigger` | number | רמת הטריגר |
| `mode` | string | `"stopbuy"` או `"close"` |
| `qtyHint` | number | הכמות באסטרטגיה (לא נאמן עליה) |

שדות נוספים ליציאה (`event = "exit"`):

| שדה | סוג | תיאור |
|---|---|---|
| `reason` | string | סיבת היציאה: `peak_trail`, `climax_exit`, `stall_detected`, `ema9_trail`, `ema20_trail`, `ema{N}_trail`, `pre_open_exit`, `stop_hit_premarket`, `stop_hit_regular_hours_backend_handles` |
| `price` | number | מחיר היציאה המשוער |

דוגמה, כניסה:

```json
{"secret":"***","v":1,"event":"entry","symbol":"WHLR","barTime":1759745340000,"tf":"1","strategy":"V05","session":"pre","price":4.06,"stop":3.78,"trigger":4.06,"mode":"stopbuy","qtyHint":25}
```

דוגמה, יציאה:

```json
{"secret":"***","v":1,"event":"exit","symbol":"WHLR","barTime":1759747740000,"tf":"1","strategy":"V05","session":"pre","reason":"peak_trail","price":3.76}
```

## 3. מה ה-Function עושה (בסדר הזה, כל שלב יכול לדחות)

1. **אימות:** `secret` תקין, `v` נתמך, כל השדות החובה קיימים ובטווח הגיוני. אחרת: `400` או `401`.
2. **מניעת כפילויות:** יצירת מסמך לפי המפתח בטרנזקציה. קיים כבר → `duplicate`.
3. **Kill Switch:** מסמך בקרה ב-Firestore. אם הוא פעיל → `rejected` (סיבה: `kill_switch`).
4. **מגבלות:** מקסימום עסקאות ליום, הפסד יומי מקסימלי, מקסימום הזמנות לדקה. חריגה → `rejected`.
5. כניסה בלבד: **אין כבר פוזיציה או הזמנה פתוחה בסמל** (בדיקה מול TradeZero). אחרת → `rejected` (`already_in_position`).
6. כניסה בלבד: חישוב גודל פוזיציה (תקרת מניות, 1% מההון מול מרחק הסטופ), ושליחת פקודת Limit (טריגר + 0.5%). בשעות הרגילות גם סטופ אמיתי.
7. יציאה בלבד: אם אין פוזיציה → `ignored` (נרשם). אחרת: ביטול הסטופ התלוי, ואז סגירה.
8. **רישום:** כל הודעה, החלטה וסיבה נרשמות ב-Firestore, גם הודעות שנדחו.

## 4. תשובה

JSON עם סטטוס HTTP:

| מצב | HTTP | גוף |
|---|---|---|
| התקבל וטופל | 200 | `{"ok":true,"status":"accepted","orderStatus":"..."}` |
| כפילות | 200 | `{"ok":true,"status":"duplicate"}` |
| נדחה על ידי הגנה | 200 | `{"ok":true,"status":"rejected","reason":"..."}` |
| יציאה בלי פוזיציה | 200 | `{"ok":true,"status":"ignored"}` |
| הודעה פגומה | 400 | `{"ok":false,"error":"..."}` |
| סיסמה שגויה | 401 | `unauthorized` |

## 5. מצבי הפעלה

- ✅ **DRY_RUN** (ברירת מחדל): ה-Function עושה את כל השלבים, אבל **לא** קוראת ל-TradeZero ורק רושמת מה הייתה שולחת.
- אחרי שהלוגים נראים תקינים: מעבר ל-**Paper**.

## 6. שאלות פתוחות

1. ⚠️ **זמן תגובה:** TradingView ממתין לתגובה זמן קצר בלבד (כ-3 שניות, לא אומת כאן). ❓ לשלוח תשובה מיד אחרי השלבים 1–4 ולהמשיך ל-TradeZero ברקע (עלול להיקטע ב-Cloud Functions), או לחכות לסיום ולקבל סיכון של Timeout בצד TradingView?
2. ❓ סטופ אמיתי בשעות רגילות בלבד (כמו ב-STATE). בפרה-מרקט: בדיקה בסקר (Dead-man's switch), עדיין לא מתוכנן בפירוט.
3. ❓ הפסד יומי מקסימלי ומקסימום עסקאות ליום: איזה ערכים להתחיל בהם?
4. ❓ האם `price` ביציאה משמש לביצוע (Limit) או רק לרישום? ההצעה: פקודת Market/Limit אגרסיבית, והמחיר רק לרישום.
